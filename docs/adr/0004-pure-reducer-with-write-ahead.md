# The core is a pure reducer with write-ahead persistence

The director core is a pure function `(state, input) → (new state, effects)`. Its inputs are adapter snapshots and signals, command results, timer firings, user actions and Check changes. Its effects are commands, notifications, events and timer arm/cancel. There is no long `await`: every wait is a status plus a persisted absolute deadline. Before any side-effecting command is sent, the new state, including a "command intent issued at T" record, is saved (atomic Store, awaited). We chose this over a conventional async coordinator because a Run can last hours across HA restarts. A restart must be able to tell that a command may already have gone out, and every rule must be testable as a table row without HA. When the Run and Schedule state machine ticket settled this, it was cheap to change. Once implemented, though, every outcome rule, the restart reconciliation table and the bulk of the test plan hang off it.
